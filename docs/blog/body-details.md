# Verbalized / prompting baselines — precise details (for blog post)

## Mechanics (exp 05)
- The verbalized prompt puts the code BEFORE the question with a minimal neutral preamble: `"Here is a code snippet:\n\n```\n{code}\n```\n\nDoes the code above contain a security vulnerability? Respond with ONLY one word — \"yes\" or \"no\" — and nothing else."`, rendered as a single user turn via `apply_chat_template(add_generation_prompt=True)` (source: `plans/cross-model-probe-generalization/05-probe-vs-verbalized/verbalized_judge.py`).
- Code-before-question is deliberate: the eliciting question comes AFTER the code so the model encodes the code the same neutral way the probe's cached activations were extracted (a question first would condition the encoding and make the comparison unfair to the probe) (source: `05-probe-vs-verbalized/EXPERIMENT.md` "Decisions").
- The yes-probability is read from a SINGLE forward pass (no generation) at the first assistant-token position: `P(yes) = sigmoid(logsumexp(logprob[yes_ids]) − logsumexp(logprob[no_ids]))` where logprob = log_softmax of the last-position logits, and yes_ids/no_ids are the first-token ids of casing/leading-space variants {Yes, yes, " Yes", " yes", YES} / {No, no, " No", " no", NO} (source: `05-probe-vs-verbalized/verbalized_judge.py`, `resolve_yes_no_ids` + `p_yes_from_logits`).
- Example-level AUC = ROC-AUC of the continuous P(yes) score against the example's vulnerable/clean label over held-out SVEN examples (1430 scored), computed over the intersection of scored eids and each probe split's test eids so both sides see identical examples (source: `05-probe-vs-verbalized/EXPERIMENT.md`).
- Qwen3-family models needed a thinking-mode guard — `apply_chat_template(..., enable_thinking=False)` plus a hard abort if the top-1 first token decodes to `<think>` — because with thinking on the first assistant token is `<think>`, not yes/no; with the guard the template pre-fills a closed empty `<think></think>` block so the first generated token is the yes/no answer (sources: `05-probe-vs-verbalized/verbalized_judge.py` `render_chat`; `RESULTS-2026-06-01-tier1-tier4.md`).

- Each specialist trains on {its CWE's positives} ∪ {all 482 fit negatives} and is scored against the general probe on the identical subset {CWE-X test positives} ∪ {146 clean test negatives}, reusing the global seed-42 group split — cells with <10 test positives are flagged LOW-n (source: `10-.../EXPERIMENT.md`, `per_cwe_probe.py`).

- Solo, every specialist is worse than the general probe overall (e.g. family:memory alone scores 0.400, cwe:CWE-089 alone 0.678 on the full test pool) — the ≈0.80 only appears when the combiner can route (source: same posthoc JSON, `specialist_solo_tokens_code`).

## exp-25 — matched-patch deconfound (`plans/cross-model-probe-generalization/25-allclean-language-matched/`)

- Matched-patch design: positives are held identical (all live-code tokens of CWE-X vuln test examples, token-labelled) while the negative pool becomes the example's OWN paired patched safe-half from SVEN — same function, same exact language — so `lang_null = 0.500` by construction and positive-side template/style leakage is also controlled (source: `25-.../EXPERIMENT.md` "Negative regimes", RESULTS.md).
- Four negative regimes were run with positives fixed: `allclean` (original 53%-Python mixed pool, the reproduction gate, where a pure language indicator scores ~0.765 = 0.53 + 0.47·0.5), `conly` (C/C++-only clean tokens, language-matched for memory), `pyonly` (Python-only clean, language-matched for injection), and `matchedpatch` (the airtight control) (source: `25-.../EXPERIMENT.md`).
- CV scheme: grouped 5-fold × 3-seed cross-validation (pair-level folds, no pair straddling; 15 pooled folds total, retrained from scratch per fold) covers `allclean` and `conly` only — matchedpatch negatives are example-intrinsic (no held-out clean pool to fold), so the decisive control's robustness rests on 1000× bootstrap-over-examples CIs instead (source: `25-.../RESULTS.md` Cross-validation section).
- Qwen2.5-Coder-32B L25, allclean-trained probes on trusted memory CWEs: CWE-125 (n=19) allclean 0.732 → conly 0.675 [0.613,0.745] → matchedpatch 0.633 [0.575,0.701]; CWE-416 (n=14) 0.766 → 0.714 [0.595,0.824] → 0.610 [0.514,0.709] (marginal); CWE-476 (n=16) 0.640 → 0.579 [0.517,0.676] → 0.544 [0.483,0.633], CI includes chance (source: `25-.../RESULTS.md`, `results/deconfound_qwen32b.json`).
- gemma-3-1b-it L25, same design: CWE-125 0.734 → 0.668 [0.599,0.741] → matchedpatch 0.657 [0.593,0.731]; CWE-416 0.769 → 0.697 [0.631,0.756] → 0.603 [0.525,0.677]; CWE-476 0.619 → 0.560 [0.506,0.605] → 0.507 [0.454,0.552] (chance) — so CWE-125 survives the airtight control in both models, CWE-416 weakly, CWE-476 collapses (source: `25-.../RESULTS.md`, `results/deconfound_gemma1b.json`).
- conly CV means (15 folds, mean ± std) corroborate stability: CWE-125 0.662±0.047 (qwen) / 0.577±0.025 (gemma), CWE-416 0.716±0.057 / 0.676±0.064, CWE-476 0.617±0.040 / 0.585±0.056, with injection positive controls rock-stable (CWE-089 ≈0.98–0.99 conly CV) (source: `25-.../RESULTS.md`, `results/cv_aggregate.json`).
- Injection positive control behaves as designed: under pyonly CWE-089 scores 0.959/0.928 (qwen/gemma) and under the stricter matched-patch 089/078/022 stay strong (0.93/0.83/0.77 qwen) but CWE-079 (XSS) drops to ≈chance (0.532 qwen) — its all-clean score was template/language, not function-local (source: `25-.../RESULTS.md` positive-control section).
- The reproduction gate passed bit-exactly: re-evaluating the held-fixed all-clean probes reproduces exp-21's `transfer_allclean.json` diagonal with max |Δ| = 0.000000 across all 9 CWEs and both models before any deconfounded number was reported (source: `25-.../RESULTS.md`, `results/repro_gate_*.json`).

## exp-27 — surface baselines under matched-patch (`plans/cross-model-probe-generalization/27-matchedpatch-surface/`)

- exp-27 re-runs exp-24's surface baselines (char-n-gram LR, combined window model, token-unigram LR, keyword-LR, keyword-untrained, lang-indicator, plus conly-trained refits of char/combined), allclean-trained and held fixed, across the three eval regimes allclean → conly → matchedpatch on two tokenizer axes (Qwen2.5-Coder-32B, gemma-3-1b), with the probe columns cited from exp-25's `deconfound_*.json` rather than re-run (source: `27-.../RESULTS.md`).
- Under matched-patch the entire window/n-gram surface family hits chance: char-ngram, combined, conlytr-char, and conlytr-comb all have 95% CIs containing 0.5 in all 6 trusted memory cells (2 axes × CWE-125/416/476), and the all-clean surface numbers drain monotonically as the confound is removed (e.g. qwen char on CWE-125: 0.610 → 0.577 → 0.545 across allclean → conly → mp) (source: `27-.../RESULTS.md` decisive tables).
- Token identity is the exception: a token-unigram LR retains 0.591 [0.561,0.621] (qwen) / 0.584 [0.543,0.617] (gemma) on CWE-125 under matched-patch — both CIs exclude 0.5 — so the matched-patch lexical ceiling on CWE-125 is ≈0.59, not 0.5 (source: `27-.../RESULTS.md`, `results/exp27_*_axis.json`).
- Probe-over-surface margins under matched-patch: the exp-25 specialized probe beats the best surface point estimate in all 4 trusted CWE-125/416 axis-cells — CWE-125 0.633/0.657 vs unigram 0.591/0.584 (+0.042/+0.073) and CWE-416 0.610/0.603 vs best surface 0.542/0.534 (+0.068/+0.069, where every surface variant's CI includes chance) — but no probe-vs-surface contrast is CI-separated at n=19/14, and the paired probeG−unigram Δ-bootstrap on 125-mp is [−0.024,+0.117] (Δ>0 in 92% of resamples, qwen) / [−0.052,+0.065] (51%, gemma) (source: `27-.../RESULTS.md`).
- Margin accounting in point estimates: of the specialized probe's margin-over-chance on CWE-125 matched-patch (0.133 qwen / 0.157 gemma), the token-identity bar covers 0.091/0.084 — roughly half to two-thirds of the residue is reproducible lexically, leaving a +0.04–0.07 probe excess that is directionally consistent across both models but not demonstrated at 95% (source: `27-.../RESULTS.md` margin accounting).
- Injection stays lexical even under the airtight control: on CWE-089 (n=44) the char-n-gram baseline scores 0.975 [0.957,0.987] on both axes, beating the specialized probe (0.933 qwen / 0.886 gemma), and similarly on CWE-078 (0.872/0.876 vs 0.833/0.771) — so probe injection numbers should never be cited as representational evidence (source: `27-.../RESULTS.md` injection positive controls).
- Repro gates (all hard-passed every run): exp-24 design-2 re-run bit-reproduces all 9 CWE × 7 column all-clean cells with max |Δ| = 0.00e+00; every (CWE × regime) cell's pos/neg token counts exactly equal exp-25's (e.g. qwen mp negatives 10413/4126/6186 for 125/416/476); and the lang-null AUC matches exp-25 to 1e-9 (mp/conly ≡ 0.500 by construction) — with the caveat that only the qwen axis is bit-anchored, the gemma axis is counts-and-nulls-pinned (source: `27-.../RESULTS.md` provenance gates).


# Dataset / training / metric (agent return, pasted)

- SVEN dataset: 1,430 examples = 715 vuln/safe pairs (bstee615/sven); languages Python 756 / C 574 / C++ 100 examples; 9 CWEs: CWE-089 (203 pairs-worth), 078 (105), 125 (103), 476 (65), 416 (56), 022 (53), 079 (49), 787 (47), 190 (34).
- Token labels: SVEN diff char-offset ranges mapped to token indices via tokenizer offset_mapping (src/data/extract_token_activations.py); positives = changed-span ∩ live-code; sanitizer spans negative.
- Split: group-clean 20% held-out test (seed 42), pairs grouped by (file, func) so before/after never straddle; internal 90/10 train/val (seed 7); layer selection on a separate 15% group-aware val carve (seed 42).
- Loss: L = (1−ω)·Σ token-BCE + ω·BCE(span-max), ω annealed linearly 0→1 over training; α=1 (exp-03: α=10→1 buys +0.012–0.033 example-AUC, token-AUC flat); AdamW lr=1e-3, wd=1e-4, 30 epochs, batch_examples=8; no activation normalization; probe = nn.Linear(d,1).
- code_only_mask (src/eval/code_mask.py): tree-sitter drops comments, imports/includes, function/class signatures (bodies kept), decorators, preprocessor directives; ~30% of tokens dropped.
- exp-07: train-time masking of trivial negatives is a no-op, Δ ∈ [−0.013, +0.002] across 8 models.
- exp-19: 478 subtractive pairs vs 237 additive (34% of fixes additive); test 97 subtractive / 49 additive pairs; pair-ranking (vuln max-token-score > its fix's) 0.43 on additive ≈ chance; subtractive restriction free (0.756 vs 0.755); token > line granularity on 6/7 models (e.g. gemma-27b 0.761 vs 0.744); ADR-0004: line labels made 11.2% of positive train tokens non-code.
- exp-19 CV: 5-fold × 3 seeds (15 fits), fold-std ≈ 0.024 (qwen) / 0.03–0.04 (gemma); all subtractive-vs-base gaps ≪ fold-std.
- exp-16 test pool: 292 test examples (146 vuln/146 clean), 76,489 test tokens, 4,160 positive; probe 0.7758 [0.725, 0.824].
- vLLM extraction 2.2–2.5× faster than HF, cos 0.998 agreement.
