# On LLMs' Internal Representation of Code Correctness

- **Citation** — Francisco Ribeiro, Claudio Spiess, Prem Devanbu, Sarah Nadi.
  *On LLMs' Internal Representation of Code Correctness.* arXiv:2512.07404 (Dec 2025).
  - PDF: https://arxiv.org/abs/2512.07404 · HTML: https://arxiv.org/html/2512.07404v2
- **Related (different group, different method)** — Bui et al., *Openia*,
  arXiv:2501.12934, code at https://github.com/iSE-UET-VNU/OPENIA. Deep note:

## TL;DR

An LLM carries a linear "is-this-code-correct" direction in its hidden states.
Extract it by contrasting activations on correct vs. incorrect solutions to the
*same* task (Representation Engineering / LAT), and you can rank/select code
samples **without running tests** — beating log-likelihood ranking and the
model's own verbalized confidence. The representation is **model-specific** but
**source-agnostic**: fitted on one model's states it cannot read another model's
states, yet it scores code from any author.

## Method (the bits we'd borrow)

Adapts **Linear Artificial Tomography (LAT)**, a 3-step RepE recipe:

1. **Stimulus design** — paired prompts: same task description, one correct +
   one incorrect implementation. Stimuli are *unlabeled* at fit time; the
   eval-time prompt explicitly mentions "correctness."
2. **Hidden-state collection** — activations at the **final token position**,
   every layer, no generation. Separate sets H_c (correct) / H_w (incorrect).
3. **Principal direction** — difference vectors H_diff = H_c − H_w, centered,
   then **layer-wise PCA → first principal component**; sign fixed by
   correlation with the correctness label (correct=1, incorrect=0).

Scoring: dot-product project a new input's hidden state onto the chosen PC.
**Layer selection**: pick the layer whose PC1 best separates correct/incorrect
on held-out validation. Selected layers land **middle-to-late**; the val-chosen
layer is within ~7pp of the oracle-best layer (in-distribution).

## Results (numbers worth comparing against)

Four 7–8B models: Mistral-7B-Instruct-v0.3, Qwen2.5-Coder-7B-Instruct,
OpenCoder-8B-Instruct, CodeLlama-7B-Instruct. Benchmarks: HumanEval (151 tasks),
BigCodeBench (457 tasks). Incorrect implementations generated by *other* models
(incl. **Gemma-3-1B**, Llama-3.2-3B, Granite-3.3-2B for HumanEval; GPT-4o,
Gemini-2.0-Flash, Llama-3.3-70B for BigCodeBench).

- **RQ1 multiple-choice (pick the correct impl):** LAT beats best baseline by
  **+8.7–26.2 pp** (HumanEval) and **+13.3–29.0 pp** (BigCodeBench). Standard
  log-likelihood ("intrinsic") is near-useless: ~5–6% on BigCodeBench.
- **RQ2 ranking (pass@rank-k):** LAT rank-1 ≥ baseline pass@1 for all models;
  e.g. Mistral HumanEval 41.3% vs 34.7%, and by rank-5 reaches 64.5% (ceiling
  67.8%). Beats RankEF at rank-1 for all but one model/benchmark.
- **OOD fitting:** representations fit on MBPP+ or synthetic stimuli often
  **match or beat** in-distribution fitting (FitMBPP+ > FitBCB on BigCodeBench).
